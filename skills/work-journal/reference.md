# work-journal reference

## セッション記録の場所

ローカルのプロジェクト別ディレクトリ配下にある、セッション ID ごとの記録ファイルを読む。

- 場所はワークスペース絶対パス由来のプロジェクト識別子の下にある。ホーム配下ならホーム以降のセグメントが識別子に含まれる。
- ワークスペースルート変更や隔離 worktree のあとでは、制御側と別のプロジェクト識別子になる。
- 記録は行単位の構造化ログ。user / assistant の発話と、終了ステータスを含むことがある。
- 日時は user 発話内の時刻表示を根拠にする。
- 異常終了や中断のステータスは未完了・ブロッカー候補。
- ツール呼び出しの細部は要約し、依頼・成果・検証・未完了だけ残す。

## `~` ツリー区画

プロジェクト未指定の recap は、期間内ヒットをホーム起点の区画へ振り分ける。**具体的な区画名・識別子をこのファイルに固定しない。** 実行時にホーム直下を見て決める。

1. `~` の子ディレクトリ名を列挙する（名前をここに書かない）。
2. 各プロジェクト識別子について、ホーム以降のパス断片を推定する（区切り文字の正規化で不可逆。一致はヒューリスティック）。
3. **表示名**は推定できたホーム相対パスを `~/…` で表す。深さは次のとおり:
   - ホーム直下の 1 段目までを基本区画とする
   - その直下にさらにリポジトリ／隔離ディレクトリ群が並ぶルートは、**2 段目まで**を区画とする（3 段目以降の番号やリポ固有名で割らない）
4. ホーム外・推定不能は表示名 `other`。
5. ユーザーがパス・識別子・区画（`~/…`）を指定したらその範囲だけに絞る。
6. 同一セッション ID が制御と隔離側の両方にあれば 1 件にまとめ、全文がある方を採用する。
7. ヒットした区画の一覧だけを「調査範囲」に書く（ゼロ件の区画は書かない）。

## 会話検索

- クライアントが会話検索を提供しているときだけ使う。手順や内部 API 名はこの skill に書かない。
- 得られるのは識別子・タイトル・短い抜粋。全文ではない。
- クエリは短く保つ。条件を詰めすぎるとヒットしないことがある。
- 識別子がセッション記録と一致すれば全文優先。不一致・記録なしは「概要のみ」。タイトルや更新時刻だけで推測結合しない。
- 概要のみで区画が推定できなければ `other`。
- リモートやアーカイブは検索に載る保証なし。見つからなければ「取得不可」。

## 外部補助（入力のみ）

recap の補助ソース。**save 先にはしない。** 接続・権限・クライアント連携があるときだけ読む。手順・ツール名・社内ホスト・スペース ID はこのファイルに書かない。

| 種別 | 読むもの（例） | 使わない |
|------|----------------|----------|
| コードホスト（GitHub 等） | 期間内の PR / Issue / レビューの有無と短い要約 | CI 秘密・差分全文の貼り付け・未公開ブランチ推測 |
| チャット（Slack 等） | 指定チャンネル／スレッドの期間内やり取りの要約 | 全チャンネル横断の無断巡回・メンション全文・DM の勝手取得 |
| wiki・ドキュメント（Confluence 等） | 指定スペース／ページの期間内更新・コメントの要約 | ページ本文の長文転記・権限外スペースの探索 |

### 使い方

1. ユーザーがリポ・チャンネル・スペース・URL・検索語を示した → その対象だけ期間で絞る。
2. 対象未指定 → 種別ごとに「取得不可」。接続があっても横断照会・「自分の活動」の勝手取得はしない。
3. 認証失敗・権限なし・未接続は失敗扱いにせず「取得不可」でセッション側の recap を続ける。
4. セッション記録と突合するときは裏付け・穴埋め。矛盾は併記し、片方に寄せない。
5. 根拠には種別と参照名（リポ名、チャンネル名、ページタイトル等）だけ。トークン・内部 ID・本文は載せない。
6. 機密・個人情報ルールは外部由来にも同じ。

### 運用上の注意（skill 外）

- 既定のリポ／チャンネル範囲をスケジュール prompt に渡すのは運用側（skill は未指定で補完しない）
- レート制限・監査ログ・プライベートチャンネル閲覧ポリシー
- 外部だけ見て「作業した」と断定しない（セッション無しの活動は出典を明記）

## 期間の既定

| 条件 | 期間 |
|------|------|
| ユーザー指定あり | その範囲 |
| なし | 直近の金曜 18:00 JST 〜 現在 |

日跨ぎセッションは、期間に重なる時刻を持つターンを含める。欠損時刻は日付窓から外さず、根拠に「時刻不明」と書く。

## ジャーナル保存先

- ユーザーまたはスケジュール prompt が明示する絶対パス（ファイル）。
- シェル環境変数を未指示で読まない。ディレクトリや skills 正本リポジトリ配下・未指定の `logs/` は新規作成しない。
- 親ディレクトリが無い・書けない場合は追記せず、ブロック出力 + 失敗理由。
- 突き合わせ・冪等は `session:<id>` の有無。ID 不明は追記しない。

## 運用上の問題点（skill 外・別途）

- 保存先・ローテーション・バックアップ・アクセス権の主体
- 未指定 recap は複数区画を横断する。共有・貼り付け先に注意
- セッション終了検知不可 → save 漏れは運用で防ぐ
- 識別子 ↔ 実パスは可逆でない（区画はヒューリスティック）
- リモート／アーカイブの保持期間と全文残存の保証なし
- 検索と全文記録が一致しない会話は概要のみ
- 外部補助の接続・既定範囲・レート制限・監査は運用側
- 外部だけの活動をセッション無しで断定しない
- プロジェクト rule はこのワークスペース限定（他では skill 名指し）
- 新 skill は版管理に載せたあとでないと配備スクリプトに検出されない
- 隔離 worktree 上で配備スクリプトを走らせるとランタイムリンクが隔離パスを指す
- 同時追記の排他
- スケジュール実行の権限・失敗通知
